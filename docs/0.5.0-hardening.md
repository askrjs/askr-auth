# Auth 0.5.0 behavioral qualification

Local acceptance: Node 24.21.0, source based on develop `da89dc868b68d0b7d97fbf44eab56669601a1bb8`. Versions remain 0.4.x during preparation; no tag, release or publication is authorized by these checks.

## Inspected baseline

The unmodified package passed `npm run check`: 159 unit cases and 15 installed Chromium browser cases. Assertion bodies and their source paths were inspected before extending them. Existing tests already cover signed RS256/ES256 tokens, algorithm/key mismatch, issuer/audience rejection, malformed UTF-8/base64url/JSON, nonce/state mismatch, discovery failure/recovery, and unknown-key refresh/cooldown concurrency. The earlier test named “rotated key” supplies the same key; the new test rotates between two independently generated key pairs.

Existing SAML assertions cover signed issuer/audience/recipient mismatch, signed outer responses, encryption, missing signatures, multiple assertions, malformed input and atomic concurrent replay consumption. Existing TOTP cases exercise RFC hash vectors, drift and Base32 failures. Existing WebAuthn tests cover size bounds, valid ES256 enrollment/assertions and stored-counter rollback. Existing browser assertions exercise one-time redirects, expiration, duplicate callback parameters, transport correlation, shared renewal, cancellation/disposal and late-response suppression.

## Reproduced defects and regressions

| Boundary                   | Original result                                                                                                                                                           | Corrected result / evidence                                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| JWT validator/issuer clock | `NaN`/negative infinity can accept an expired signed token; non-finite timed issuance serializes null time claims; extreme finite time can produce no advancing lifetime. | Finite seconds required; expiration must be finite and advance. Failed operations recover with valid time, including clock failure during asynchronous JWKS refresh. |
| Session resolver clock     | Negative infinity permits an expired opaque session; invalid time has no explicit operational failure.                                                                    | Non-finite millisecond clocks reject with `TypeError`; exact expiry is anonymous and the previous millisecond is authenticated.                                      |
| SAML clock/time policy     | Invalid clock bypasses assertion/request expiry comparisons; invalid skew/age/lifetime is accepted.                                                                       | Finite valid Date-range time and bounded policy required. Failed validation does not consume the request. Unrepresentable request lifetime fails before persistence. |
| TOTP counter boundary      | Invalid time leaks conversion errors or produces invalid counters; epoch window accepts counter -1 by unsigned wrap to `2^64 - 1`.                                        | Structured malformed-input error for invalid/negative/unrepresentable time. Skip invalid drift steps; accept real epoch counter 0.                                   |
| OIDC client binding        | Signed single-audience token with a different explicit `azp` is accepted; additional audiences have no configured trust policy.                                           | Bind explicit `azp` to the one configured client ID; reject another audience. String and single-element-array client audiences succeed.                              |

The first 35-case protocol probe produced 14 failures and 21 characterizations. The SAML clock/policy extension produced ten failures plus existing/characterization passes; the authorized-party and additional-audience probes each reproduced one distinct failing case. The session-clock extension reproduced three invalid-clock cases. These are related boundary cases, rather than one independent defect per failing input. All retained regressions now pass. The clock failures require invalid application-supplied time or configuration; signatures are verified in the JWT/SAML artifact probes.

## Standards used for interpretation

[RFC 7519](https://www.rfc-editor.org/rfc/rfc7519) defines NumericDate and exp/nbf boundaries and permits a parser that retains the last duplicate member. [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238) defines the time-step counter; [RFC 4226](https://www.rfc-editor.org/rfc/rfc4226) defines the unsigned moving factor. The library bounds counters to JavaScript safe integers rather than silently wrapping or rounding.

[OpenID Connect Core, ID-token validation](https://openid.net/specs/openid-connect-core-1_0.html#IDTokenValidation) requires audience trust; this package's narrow client profile supplies one trusted client ID and consistently checks an explicit authorized party. [WebAuthn assertion verification](https://www.w3.org/TR/webauthn-3/#sctn-verifying-assertion) supplies the ceremony binding reference. Application policy/storage, including atomic replay/counter persistence, remains application-owned.
