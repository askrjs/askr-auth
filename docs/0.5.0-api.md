# Auth 0.5.0 API review

Historical baseline: npm `@askrjs/auth@0.4.2`, source `3a301850a9845a4a049e5bcc928e4b2626afc33c`, had 93 entrypoint/name pairs. The original contraction retained 83 and removed ten implementation helpers. Auth65 now also removes the six-name browser session entry and withdraws the develop-only two-name SDK adapter. The native server engine and four provider presets add 24 names.

The prepared final declaration contract expects **101 entrypoint/name pairs (33 values, 68 types), 12 export-map keys**. This is the complete source-owned expectation in `tests/public-contract.json`, not a claim of freshly compiled/installed qualification. Actual TS6/TS7, runtime, archive and all24/generated-consumer readback must reconcile this inventory after carry-forward and normal SDK lock pruning. No compatibility aliases are added.

## Migration and qualification

Use `createOidcClient(...).exchangeCode({ code, state, request })` for OIDC ID-token validation; its required stored request provides nonce/state correlation. Resource tokens continue through `createJwtValidator`. General-purpose CBOR/COSE decoding is outside Auth; use a dedicated codec library. The passkey client operations accept and return canonical base64url fields, so application call sites do not need Auth encoding helpers. `CoseAlgorithm` remains public because the persisted registration result exposes it.

The original seven-entrypoint/83-name installed checks are historical evidence for the earlier contraction; see [the dated behavioral record](0.5.0-hardening.md). The retirement gate retains all positive names in the final contract, the ten original name negatives and strict TS6/TS7 denial of both removed entries and private implementation paths. Runtime imports require `ERR_PACKAGE_PATH_NOT_EXPORTED` for the retired keys, and the normally installed graph must contain no Auth0 SPA SDK. Surviving `/oidc` browser primitives and all four native provider flows remain distinct required gates. None of these new retirement gates has executed in this source-only proposal.

Session clocks use finite Unix milliseconds; JWT clocks use finite Unix seconds; SAML clocks use valid Date-range Unix milliseconds. Invalid clocks/time policies raise operational `TypeError`. TOTP rejects invalid/negative/unrepresentable timestamps with `MfaValidationError("malformed-input")` and skips out-of-range drift counters. Explicit OIDC `azp` must identify the configured client, including tokens with one audience. OIDC ID tokens containing another audience are rejected: this client configures trust for one client ID, without an additional-audience trust option. These are input-contract fixes, not new storage or replay policy.

## Withdrawn Auth #61 browser SDK addition

The develop-only `@askrjs/auth/auth0` addition (`createAuth0Session` value and
`Auth0SessionOptions` type) is REMOVE. It was not published in the 0.4.2 baseline.
Its optional SDK peer and browser-session adaptation are withdrawn together;
`@askrjs/auth/providers/auth0` is the separate retained native server preset.
The earlier 85-name/nine-key and optional-peer receipts are historical only.
Bounded generic OIDC `authorizationParams` remain supported; browser-session
`silent.responseFormat` disappears with that session model.

## Browser-session migration

Remove imports from `@askrjs/auth/browser` and the develop-only
`@askrjs/auth/auth0`; both public keys and their declarations are unavailable.
Remove the Auth0 SPA SDK dependency if it was installed solely for that adapter.
Do not substitute `/providers/auth0` into browser code: the native presets and
client credentials belong to server code.

Configure `createProviderSession` from `/server` with the appropriate `/providers/*`
factory. Bind that engine to `@askrjs/server` provider auth so login, callback,
session and logout transport retain one authority owner. Use
`createSessionAuth` from `@askrjs/askr/router` for SSR/SPA public snapshots, route
requirements and explicit interaction recovery. Request API tokens only through
the server context with the configured canonical resource/scopes; identity
sign-in does not imply an API grant. Provider consent redirects do not resubmit
failed application actions automatically.

The low-level `@askrjs/auth/oidc` PKCE/exchange primitive and
`@askrjs/auth/webauthn-client` credential helpers remain public. They do not
reintroduce browser token persistence, iframe silent-session ownership or the
official SDK adapter. See the [server contract](server-session-contract.md) and
the four [Auth0](providers-auth0.md), [Microsoft](providers-microsoft.md),
[Google](providers-google.md) and [Apple](providers-apple.md) setup guides.
