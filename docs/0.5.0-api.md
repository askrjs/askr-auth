# Auth 0.5.0 API review

Baseline: npm `@askrjs/auth@0.4.2`, source `3a301850a9845a4a049e5bcc928e4b2626afc33c`. The compiler inventory contains **93 entrypoint/name pairs**; the candidate retains **83**, removing ten implementation helpers. All eight original export-map keys remain intentional. The expanded Auth #61 addition below brings the final surface to 85 names across nine keys. No compatibility aliases are added.

## Migration and qualification

Use `createOidcClient(...).exchangeCode({ code, state, request })` for OIDC ID-token validation; its required stored request provides nonce/state correlation. Resource tokens continue through `createJwtValidator`. General-purpose CBOR/COSE decoding is outside Auth; use a dedicated codec library. The passkey client operations accept and return canonical base64url fields, so application call sites do not need Auth encoding helpers. `CoseAlgorithm` remains public because the persisted registration result exposes it.

The seven intended entrypoints are normally installed from an npm tarball. Strict TypeScript 6.0.2 and 7.0.2 checks enumerate all 83 declaration names, reject all ten removals, exercise credential types and block 16 implementation paths. Runtime imports enumerate each value surface and exercise real signing/validation and TOTP boundaries. Chromium, Firefox and WebKit run the installed browser flow. See [behavioral evidence](0.5.0-hardening.md).

Session clocks use finite Unix milliseconds; JWT clocks use finite Unix seconds; SAML clocks use valid Date-range Unix milliseconds. Invalid clocks/time policies raise operational `TypeError`. TOTP rejects invalid/negative/unrepresentable timestamps with `MfaValidationError("malformed-input")` and skips out-of-range drift counters. Explicit OIDC `azp` must identify the configured client, including tokens with one audience. OIDC ID tokens containing another audience are rejected: this client configures trust for one client ID, without an additional-audience trust option. These are input-contract fixes, not new storage or replay policy.

## Expanded Auth #61 additions

The historical 93-pair review above remains unchanged: 83 kept, ten removed.
Auth #61 adds one runtime factory `createAuth0Session` and one type
`Auth0SessionOptions`, owned only by the new `@askrjs/auth/auth0` entrypoint.
The resulting inventory is **85 names (28 values, 57 types), nine export keys**.
The adapter returns existing browser session types rather than adding aliases.
Its official SDK dependency is an optional peer: native/server runtime imports
and all declarations remain usable without the SDK installed.

Retained `OidcClientOptions` adds the bounded `authorizationParams` field;
`OidcClientErrorCode` adds `invalid-authorization-params`. Retained browser session
options add explicit `silent.responseFormat` selection (`flat` by default,
`auth0` when selected). There is no replacement of native cryptographic
verification. Existing users need no migration; choose the
[native parameters/format](browser-session.md#provider-parameters-and-auth0-messages)
or the [optional SDK adapter](auth0-session.md) according to provider needs.
